P1 / W4 - AVM iOS Production Readiness

  • Keep the new make verify-libavm-ios gate green. It now builds LibAVM.xcframework, exports the embedder headers, compiles a tiny Oren source to .obc, links that bytecode into iOS device/simulator smoke binaries, and runs the same .obc through the host embed API with argv plus VirtualFS input/output, VirtualNET fixtures, VirtualPROC fixtures/default exits, and captured stdout retrieval/clear.
  • Keep make verify-compiler-in-avm-ios-chain green. It now builds stdlib_bundle.obc and oren.obc, runs the compiler .obc inside AVM with VirtualFS stdlib resources, extracts out.obc, and runs the compiled output.
  • Continue the iOS host-adapter SDK (OrenAVMKit) after the retained TIME/NET/GFX/FS slices. Current SDK package builds OrenAVMKit.xcframework, exposes deterministic and interactive app defaults, runs OBC on virtual FS/NET/PROC with stdout capture, verifies wall-clock time.sleep_ms, verifies app file/directory mounts into VirtualFS and VFS export back to host files, verifies allowlisted URLSession prefetch into VirtualNET and live allowlisted host fetch during std:net/avm.try_get_text(url), verifies binary GFX frame retrieval plus host-injected binary pointer/resize/key/text events through the GFX mailbox, exposes decoded Oren-side std:ui/avm.next_event() maps, and ships a default UIKit/CoreGraphics OrenAVMGraphicsView for the current fill_rect/text/stroke_line/circle subset. The OGF0 frame header now carries frame sequence, native drawable size, and target refresh hint metadata; AVM validates OGF0 frames and OGE0 host input events before accepting them, with curated gates for malformed frames, op-count cap rejection, frame I/O-budget rejection, input queue depth, non-1000 resize scale propagation, latest-frame replacement/clear semantics, and FIFO pointer ordering. Next: compiler helper package, package store helper, and the game-grade GUI path: display-link pacing gates, retained resource handles, Metal/MTKView, richer 2D/3D rendering, and richer text input/IME helpers. Design notes: project-doc/ios_avm_sdk_design_20260531.md, project-doc/avm_ui_render_performance_design_20260531.md.
  • Treat virtual resources as app-facing host adapters, not test-only fixtures. The iOS SDK default should make safe real work convenient, and capability-enabled performance paths should default to host-backed virtual providers rather than raw OS objects in OBC: TIME has deterministic and wall-clock modes; FS has explicit app file/directory mount and export helpers; NET has allowlisted URLSession prefetch plus an interactive-default live host-fetch callback for OBC std:net/avm, dynamic SDK enable/restrict/disable controls for user permission prompts, and a reusable SDK session for the current HTTP body path; PROC should remain virtual/app-command based on iOS rather than arbitrary subprocess; UI has binary frame/input mailboxes plus UIKit fallback and needs the Metal/game-grade path. Each default must remain capability-declared and budgeted before OBC runs.
  • Extend AVM NET beyond HTTP-style body fetch to the rest of the app-facing network surface. The performance option should be a host-backed VNET provider, not raw host networking in bytecode: TCP/UDP should expose capability-gated virtual session handles covering connect/listen/send/recv/close, DNS policy, async readiness, cancellation, byte budgets, and iOS lifecycle behavior, then map std:net/tcp / std:net/udp facades onto that protocol.
  • Add a virtual resource permission-request mailbox so OBC can request NET/FS/UI/etc intent, the host app can show user-facing permission UI, and the SDK can dynamically update provider policy without recompiling or special-casing the OBC package.
